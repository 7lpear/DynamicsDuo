# 오목판–로봇 좌표 보정 준비

이 단계는 **판 교점의 로봇 기준 XYZ를 보정하고 중앙 위 접근 경로를 계산**합니다.
실제 모터를 움직이는 기능은 아직 포함하지 않습니다. 관절 명령으로 연결하려면
그리퍼 끝점(TCP)·관절 영점/방향 검증, 역기구학, 작업 범위와 충돌 검증이 추가로 필요합니다.

저장소 루트에서 실행하세요. NumPy 외에 추가 설치는 필요하지 않습니다.
USB 상태 읽기만 기존 LeRobot 환경인 `.venv`를 사용합니다.

## 지금 진행할 순서

1. 로봇 베이스·판·카메라·돌 한 개를 제공할 받침대의 위치를 고정합니다.
2. 카메라에서 중앙과 가장자리의 좌표·흑백 판정을 확인합니다.
3. 기존 로봇 진단으로 현재 관절 상태·전압·온도·오류 상태을 확인합니다.
4. 아래 보정 세션을 생성하고, 동일한 로봇 기준 좌표계에서 판의 기준점을 측정합니다.
5. 독립 검증점을 포함한 오차 검사를 통과한 뒤 목표 XYZ와 접근 경로를 확인합니다.

```powershell
conda activate so-arm-101
python gomoku_vision/board_camera.py --camera 1 --size 9 --reset
```

빈 판에서 격자를 확인하고 `B`로 기준을 수집합니다. 돌을 중앙과 가장자리로 옮겨
좌표·흑백을 확인하고, 손/팔이 지나간 뒤 판정이 정상 복귀하는지 확인합니다.
`PAUSED` 상태는 이전 결과이므로 새로운 착수 판단에 사용하면 안 됩니다.
카메라 창을 종료한 뒤 필요에 따라 다음 진단을 실행합니다.

```powershell
.venv\Scripts\python.exe -m gomoku_robot read-state --port COM10 --robot-id follower
```

현재 팔로워는 `COM10` 기준입니다. 재연결 후 포트를 확인하세요.
진단 중 실제 동작이나 토크 활성화는 없습니다. 다른 앱이 같은 COM 포트를 사용 중이면
먼저 해당 앱의 연결을 종료하세요. 현재 진단 결과만으로 판 전체 이동이나 돌을 든 상태의
부하 용량이 검증되지는 않습니다. [관측과 텔레오퍼레이션 안내](../MOTION_VIEWER.md)을 참고하세요.

`Calibration missing or mismatched`가 나오면 먼저 현재 장비에 맞는 관절 보정 파일을
확인해야 합니다. 파일과 모터 중 어느 쪽이 검증된 값인지 확인하지 않고 서로 덮어쓰면 안 됩니다.
관절 보정(모터 영점·범위)과 아래 판 좌표 보정은 별도이며, 판 좌표 보정으로 이 오류는 해결되지 않습니다.

### 관절 보정을 다시 하는 경우

먼저 다른 로봇 앱의 연결을 종료하고, 베이스를 고정한 뒤 그리퍼를 비우고 팔을 받치세요.
모터 전원과 USB를 연결합니다. 토크가 켜져 있으면 팔을 받친 채 모터 전원을 껐다 켠 뒤 진행합니다.

```powershell
.venv\Scripts\python.exe calibrate_follower.py --port COM10 --robot-id follower
```

이 프로젝트용 명령은 PC 파일과 모터 보정값을 `calibration/robot_backups/`에 백업하고,
기존 보정값 재사용 없이 새 측정을 시작합니다. 모터 설정 전체를 적용하는 `Robot.connect()`를
호출하지 않으며, 토크 활성화·위치 이동 명령도 보내지 않습니다. 이미 토크가 켜져 있으면 중단합니다.

1. `middle of its range of motion` 안내에서 모든 관절을 움직임 범위의 중간 정도에 놓습니다.
   그리퍼도 반쯤 열고, 손목 회전은 케이블이 꼬이지 않는 일관된 정면 방향으로 둡니다.
   팔을 받치면서 Enter를 누릅니다.
2. `Move all joints except 'wrist_roll'`와 MIN/POS/MAX 표가 나오면 베이스, 어깨, 팔꿈치,
   손목 굽힘, 그리퍼를 한 관절씩 천천히 양쪽 가동 범위로 움직입니다.
   케이블이 당겨지거나 구조물이 닿으면 억지로 밀지 마세요. 손목 회전은 이 범위 기록에서 제외됩니다.
3. 다섯 관절의 MIN/MAX가 각각 변했는지 확인하고, 팔을 안정적으로 받친 상태에서 Enter를 누릅니다.
4. `Calibration saved to ... follower.json`과 `PASS: PC/device calibration match`를 확인합니다.
   종료 후에도 토크가 꺼져 있으므로 팔을 받치고 안정된 받침에 내려놓습니다.
5. 위의 `-m gomoku_robot read-state --port COM10 --robot-id follower` 명령으로 다시 진단합니다. 이후에도 `--robot-id follower`를 사용하세요.

기존 관절 각도로 저장한 자세·경로가 있다면 새 보정 기준으로 다시 확인해야 합니다.

## 좌표와 단위

- 카메라 보정 화면의 **왼쪽 위 교점이 A1**, 오른쪽으로 A→B, 아래로 1→2입니다.
- 9×9 교점판의 모서리는 A1, I1, I9, A9, 중앙은 E5입니다. I열을 생략하지 않습니다.
- `xyz_mm`는 모두 **하나의 로봇 베이스 기준 좌표계**, 단위 **mm**입니다.
- +Z는 위쪽이고 판은 베이스 XY 평면에서 20° 이내로 놓여 있어야 합니다.
- 카메라 픽셀, 보정 화면 픽셀, 관절 각도, 그리퍼 %는 XYZ 측정값이 아닙니다.
- 판 표면의 교점 위치를 기록합니다. 돌 윗면·그리퍼 몸체 위치를 섞으면 안 됩니다.

카메라의 원근 보정은 영상 안의 격자 정렬입니다. 이것만으로 로봇 XYZ는 나오지 않습니다.
현재 URDF의 베이스 원점/축과 실제 장비의 대응을 정한 뒤 일관되게 측정해야 합니다.
팔로 교점을 짚어 측정하려면 먼저 TCP 위치와 관절→URDF 방향·영점을 검증해야 합니다.
이번 도구는 이 보정이 끝나기 전에 관절 각도를 XYZ로 자동 환산하지 않습니다.

## 1. 측정 파일 생성

```powershell
python -m gomoku_robot init
```

`calibration/robot_board.session.json`을 생성합니다. 이미 존재하는 파일은 덮어쓰지 않습니다.
각 `xyz_mm`는 `null`로 시작하므로 실측 전에는 목표 계산이 차단됩니다.

파일에서 다음을 입력합니다.

| 필드 | 입력할 값 |
|---|---|
| `setup_id` | 고정 배치를 구분하는 이름. 예: `desk-layout-01` |
| `fit_points` | A1, I1, I9, A9의 판 표면 XYZ 실측값 |
| `validation_points` | 보정 계산에 사용하지 않은 E5의 독립 실측값 |
| `max_error_mm` | 최대 허용 측정 잔차. 초기값 2 mm |

`xyz_mm`에는 `[x, y, z]` 형식으로 숫자를 입력합니다. E5는 네 모서리 평균을 적지 말고
별도로 측정하세요. 가능하면 C3, G7 등도 `validation_points`에 추가하세요.
허용 오차는 돌 크기·교점 간격·그리퍼 구조에 맞춰 정해야 하며, 2 mm는 초기 개발 기준입니다.

판이나 베이스가 움직이거나 카메라 좌표 방향이 달라지면 기존 세션을 재사용하지 말고
새 배치로 다시 측정하세요. 이 도구에는 배치 이동 자동 감지 기능이 없습니다.

## 2. 보정 검사

```powershell
python -m gomoku_robot check
```

모서리들로 `XYZ = A1 + 열번호 × 가로벡터 + 행번호 × 세로벡터`를 구하고,
독립 검증점의 오차를 검사합니다. 출력의 `max_fit_error_mm`,
`max_validation_error_mm`가 설정 기준 이하여야 합니다.
교점 중복, 누락, 비정상 수치, 모서리 배치 오류, 격자 간격 불일치도 거부합니다.
이 통과는 **기하 측정의 일관성**을 뜻하며 팔의 도달성·충돌·실제 착수 정밀도 검증은 아닙니다.

## 3. 중앙 위 목표 확인

```powershell
python -m gomoku_robot target --coordinate E5 --hover-mm 30
```

`surface_xyz_mm`는 판 표면 교점, `hover_xyz_mm`는 판 법선 방향으로 30 mm 위의 TCP 목표입니다.
TCP는 실제 제어할 도구 기준점입니다. 도구나 돌의 다른 부분은 TCP보다 아래에 있을 수 있으므로,
도구 크기와 기존 돌 높이를 고려해 여유 높이를 정해야 합니다.

## 4. 접근 경로 계산

현재 TCP의 XYZ를 같은 좌표계에서 확인한 다음 실행합니다.

```powershell
python -m gomoku_robot plan-hover --coordinate E5 --hover-mm 30 --start-xyz-mm <현재X> <현재Y> <현재Z>
```

`<현재X> <현재Y> <현재Z>`를 실측 숫자로 바꾸세요. 위 꺾쇠 문자열은 그대로 실행하는 값이 아닙니다.
출력은 `start → raise → traverse → hover`의 Cartesian 경유점입니다.
출발점이 낮으면 먼저 들어 올리고, 가로 이동은 최소 지정 높이를 유지합니다.
판 표면으로 내려가거나 돌을 놓는 경로는 생성하지 않습니다.

이 경로는 TCP 점에 대한 기하 계산입니다. **관절 보간 경로가 아니며 실제 이동 명령이 아닙니다.**
로봇 본체·도구의 충돌, 도달성, 관절 제한, 자세, 부하, 최신 돌 상태는 검사하지 않습니다.
각 경유점을 관절 명령으로 바로 보내면 중간 TCP 경로도 달라질 수 있습니다.
결과를 저장하려면 `--out calibration/robot_board.preview.json`을 추가하세요.
각 명령은 원본 측정 세션을 다시 검사하므로 이전 보정 보고서를 그대로 신뢰하지 않습니다.

측정 없이 형식만 확인하는 예시는 다음과 같습니다. 예시의 숫자를 실측값으로 사용하지 마세요.

```powershell
python -m gomoku_robot demo
```

## 선택: 관절 상태 저장

```powershell
.venv\Scripts\python.exe -m gomoku_robot read-state --port COM10 --robot-id follower --out calibration/robot_board.pose.json
```

명시적으로 USB에 연결하여 현재 관절 위치·전압·온도·토크 상태·Status를 저장합니다.
모터 위치, 토크, 보정값을 쓰지 않으며 종료 시 기존 토크 상태도 유지합니다.
팔이 꺼진 상태라면 계속 받쳐 두어야 합니다. 연결 실패나 보정 불일치 시 저장하지 않습니다.
저장된 관절 위치는 재현과 분석용이며 `xyz_mm`에 넣을 수 없습니다.
이 기능은 전체 부하 진단을 대체하지 않습니다.

## 다음 구현 단계

카메라·브래킷 구성이 바뀌면 [읽기 전용 모니터](../MOTION_VIEWER.md)를 먼저 사용합니다.
`monitor_follower.py`는 각도·전류·부하·전압·온도를 관측하며 모터를 움직이지 않습니다.
관측값만으로 새 장착물의 질량이나 실제 착수 동작의 부하 용량을 확정할 수는 없습니다.

실측 보정 확인 후 TCP와 관절–URDF 대응을 검증하고, 역기구학과 실제 작업 영역에 대한
경로 검사를 연결합니다. 그다음 돌 없이 중앙 위로 저속 접근하고, 중앙에서 돌 하나 집기·놓기를
확인합니다. 착수 후 목표 칸에 원하는 돌이 생기고 기존 돌이 유지됐는지 확인한 뒤 범위를 넓힙니다.
